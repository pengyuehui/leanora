# 实施与验收

按用户六项要求执行。合并后底部为「历史、动作、饮食、我的」，默认进入历史；今日内容置顶，使用时钟图标，移除太阳。参考用户提供截图的结构和交互，不复制图片或竞品内容；使用已有离线动作图。

- [x] U1 Health：自动同步首次开启必须经过系统授权请求；暂停后保留访问选择；保存失败不显示已连接；保留可定位的错误及权限恢复路径。不推断读取权限、不扩大访问范围、不自动重导历史。核对读入、写出、重试与真实系统授权。
- [x] U2 历史：合并今日概览，月历按周一到周日固定七列；历史/统计切换与训练/身体/饮食筛选；月切换、回到今天、记录标记、选日详情与来源操作。没有记录不当作零。
- [x] U3 动作：训练 Tab 改动作浏览，左侧肌群、顶部器械与收藏/最近筛选、搜索、离线图片卡片、自定义动作；训练、模板、计划从明确的训练入口进入，原选择动作流程保留。
- [x] U4 文案：删除主页面营销和重复说明，保留单位、未知值、来源许可、权限、历史导出和删除确认等必要信息。
- [x] U5 验证：核心测试、原生构建、关键 UI 回归、普通/大字体深色截图与代码审查，保存真实通过和剩余真机范围；按既定格式提交。此请求不包含新版本送审或公开上架。

Health 初查：HealthConnectionView 的自动同步开关只 configure/sync，未请求授权；恢复访问选择被 configuration.enabled 条件限制。需用测试验证修复，不将其直接断言为用户真机唯一原因；已请求用户补充症状。

验证重点：跨年/闰月/DST、月首星期一、相邻月日期、类型筛选、动作收藏与自定义、训练开始/继续及模板可达性、Health 请求失败/取消/保存失败/暂停恢复、真实授权后组件写出。健康真机验收与模拟器测试分别记录。既有三个未提交工程/资源文件保持。

完成：核心 154 项中 152 通过、2 项既有容量跳过、0 失败；4 个原生 Health 单元和 10 个不同 UI 用例分批最终通过，最后一批 6 项全过。真实系统权限和 65.4 kg 写回在新模拟器通过。用户补充为“不弹系统授权/请求失败”，未取得其物理设备错误码，不认定唯一真机原因。14 张来源可追踪的截图、审查与全部失败/修正历史见 [专项 QA](../../app/docs/qa/history-actions-health-20261107/README.md)。
