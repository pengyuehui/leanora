# Leanora Fitness 1.2 版本计划

目标：从“能完整记录”改进为“可以随时开始、少重复输入、训练成果能复用”。本轮实现下列六项，并验证、保存代码及向 App Store 提交 1.2（下一可用构建号计划为 6）。提交成功以 Apple 的审核详情为准，审核通过后沿用手动发布。

## 对照与依据

需求来自本次用户请求、[开发参考报告](../../analysis/训记与薄荷-开发参考.md)和训记开发者在 [App Store](https://apps.apple.com/cn/app/id1464915553) 的公开产品说明。报告中的 Android 页面/SQL 是静态证据，不能当作已实测的现行界面；公开说明用于确认记录、计划、自定义输入和历史分析的产品方向。实现保持独立，不导入训记的代码、图片、视频、文案或训练计划。

| 参考价值 | Leanora 现状 | 1.2 的具体交付 |
| --- | --- | --- |
| 临时开始记录 | 必须先保存模板，执行页只能增减组 | 自由训练；训练中添加、移除和调整动作顺序，支持改训练名称 |
| 最近训练就近参考 | 已有历史预填，但没有明确的来源对照 | 显示上次训练日期与完成组；明确“沿用上次”，只修改未完成组 |
| 重复训练少输入 | 能看历史，没有再练入口 | 已完成历史“一键再练”，复制已完成组的实际值与类型，新时刻、新 ID，不自动完成 |
| 计划与实际分开 | 模板能编辑、复制，完成训练不能回用 | 完成训练可存为新模板；原模板版本未变化时可明确更新，保留名称与周安排 |
| 常用动作易找到 | 882 个动作，已有图示、搜索和多维筛选 | 全部 / 收藏 / 最近训练分组，收藏随备份保存、重启保持 |
| 内容帮助用户起步 | 882 动作均有离线图片，缺少范例计划和记录教学 | 4 套原创范例计划、共 9 个可编辑模板；8 篇原创记录指南；复用现有离线动作图示 |

本轮不增加视频、云账号、收费、AI 营养处方或 Apple Watch App，不修改已发布的隐私收集答案。部分动作名称/步骤仍保留英文。范例用于帮助建立可编辑记录，不按个人健康信息生成训练处方。

## 验收要求

### 开始与重复记录

- R1：无需模板即可开始；重启继续同一训练；已有进行中训练时返回它，不创建第二份。
- R2：动作增减、排序、改名可落盘；移除超级组成员后解除另一成员的配对，提醒不会引用已移除组；完成训练及已有历史快照不自动改变模板。
- R3：上次参考排除当前训练、未来训练、未完成/删除记录及计量不匹配记录；沿用不覆盖已完成组，不复制计时状态、完成时刻或主观强度。
- R4：再练产生独立训练和所有新嵌套 ID，保留已完成组类型，清空时刻/暂停/完成/计时，开始时不创建健康写入任务；原历史保持原样。

### 模板、常用动作和内容

- R5：模板保存只提取已完成正式组，组数按实际正式组数、目标取首个正式组；其他类型仍保留在历史。更新原模板需明确确认且通过修订校验；旧模板被修改或删除时改存新模板。
- R6：收藏支持旧 JSON 解码、磁盘重启及备份恢复；最近动作按已完成训练中的完成组推导，可与现有搜索筛选组合。
- R7：4 套计划（全身基础、哑铃全身、徒手基础、推拉腿）共 9 个模板及 8 篇指南可离线浏览；预览不写库，明确采用后整体原子保存，默认不覆盖用户的周安排。

### 验证与发行

- R8：完成基础回归、真实存储与健康队列边界、原生 UI 主流程和大字号检查；发行包验签、图片与许可核验；Apple 显示正确版本和构建等待审核。

## 实现约定

- 沿用 `AppModelActor` 作为唯一写入端、`TrainingStore.run` 的忙碌/错误处理及真实 SwiftData 测试模式。自由训练和模板导入需要的目录依赖与业务记录在同一事务保存。
- 收藏使用 `Exercise` 可选附加字段，旧数据缺失时视为未收藏；不增加 SwiftData 实体或改变备份版本，原目录 ID 保持。
- 历史复用和模板投影采用基础层的纯值转换，UI 不复制业务规则。上次参考按当前训练开始时刻固定截止；重复动作优先按模板项目匹配，避免互相串值。
- 所有修改保留修订冲突检查。新建训练、增减动作和保存模板不会写 Health；只有完成训练才沿用现有健康队列，既有幂等、恢复核对和删除边界继续有效。
- 模板更新只影响未来；名称、周安排沿用原模板。范例计划和指南是项目原创文本，指导图片继续保留各自许可与署名。
- 保留现有未提交的 `Localizable.xcstrings`；构建不回写提取文件，提交仅包含本轮文件。
- 收藏/最近为空时分别说明如何收藏或完成训练，提供返回全部动作；按钮保留明确朗读标签和至少 44 pt 点击区域，超大字号使用纵向回落，不把关键动作仅放在滑动菜单内。
- 上次参考以已完成训练的结束时刻早于当前开始时刻为边界；相同时刻用稳定 ID 排序，重复读取结果一致。

## 实现单元

- [x] **U1：自由训练与执行中的动作管理（R1、R2、R8）**

文件：修改 `app/ios/Leanora/Core/Training/WorkoutRepository.swift`、`Features/Training/TrainingStore.swift`、`Features/Training/TrainingHomeView.swift`、`Features/Workout/ActiveWorkoutView.swift`；新增基础规则文件 `Core/Training/WorkoutReuse.swift` 和测试 `app/ios/LeanoraTests/WorkoutWorkflowTests.swift`。

做法：开始空训练，复用动作选择器；添加动作同时保存目录依赖与独立快照；结构调整只用于活动/暂停训练，移除前确认并规范顺序/配对。标题可改，空训练不能结束但可以放弃。

测试：空训练开始/重入/磁盘恢复；添加内置与自定义动作；拒绝归档动作、过期修订和终态修改；移除配对动作解除关联；事务失败不留下半份动作或训练；完成前没有健康任务。

- [x] **U2：上次表现与历史再练（R3、R4、R8；依赖 U1）**

文件：修改 `Core/Training/WorkoutEngine.swift`、`WorkoutRepository.swift`、`Features/History/WorkoutHistoryView.swift`、`Features/Workout/ActiveWorkoutView.swift`；测试 `WorkoutWorkflowTests.swift` 与现有 `WorkoutSessionTests.swift`。

做法：统一上次表现选择与预填规则；执行页展示日期、已完成组和正式组容量口径；手动沿用只作用于尚未完成的组。历史列表可再练，复制上次已完成组，重新分配训练/动作/组/配对 ID，脱离旧日历安排。

测试：跳过未来/当前/删除/未完成/计量变化记录；同动作重复模板项目分别匹配；热身与正式组不串值；保留已完成组；再练清理全部时间状态和旧关联，原历史不变；归档动作报错；已有活动训练时只返回原训练。

- [x] **U3：完成训练回用模板（R5、R8；依赖 U1）**

文件：修改 `Core/Training/TrainingRepository.swift`、`WorkoutReuse.swift`、`Features/Workout/ActiveWorkoutView.swift`，复用 `Features/Training/TemplateEditorView.swift`；测试 `WorkoutWorkflowTests.swift`。

做法：先生成可审阅的模板草稿，再走现有编辑保存流程。只采用已完成正式组；纯热身/递减等不能生成空模板。更新原模板时保留名称与安排，要求原模板修订未变；保存前再次用现有修订校验保护并发编辑。

测试：混合组类型的目标与组数；没有正式组报错；新模板全部新项目 ID；更新原模板不改历史、名称和周安排；原模板更新/删除、动作归档、提交期间冲突不覆盖资料；取消草稿不写库。

- [x] **U4：收藏与最近动作（R6、R8）**

文件：修改 `Core/Domain/WorkoutModels.swift`、`Core/Training/TrainingRepository.swift`、`TrainingStore.swift`、`Features/Training/ExerciseLibraryView.swift`；测试 `WorkoutWorkflowTests.swift`、现有 `BackupTests.swift`。

做法：可选收藏字段；详情和列表提供收藏入口，选择动作时也可筛选。最近动作仅由未删除的已完成训练中实际完成组推导，最多 20 个，遵循现有归档和搜索筛选。

测试：旧目录/备份解码；收藏开关、重启、导出恢复；搜索和收藏组合；删除/放弃/未完成记录不进入最近；归档动作不混入默认结果；保存失败仍保留原状态。

- [x] **U5：原创内容与训练首页（R7、R8；依赖 U1、U4）**

文件：新增 `Core/Training/TrainingContentCatalog.swift`、`Resources/Catalog/training-content.json`、`Features/Training/TrainingContentView.swift`；修改 `TrainingHomeView.swift`、`TrainingRepository.swift`、Xcode 工程及生成脚本所需资源引用；测试 `app/ios/LeanoraTests/TrainingContentTests.swift`。

做法：计划预览展示器械、动作、组/次数及来源；“采用计划”才创建个人模板，可继续编辑。4 套计划对应 2+2+2+3 个模板，全部使用已有中文常用动作和指导图片；8 篇指南解释组类型、目标与实际、休息/暂停、主观强度、统计、复用、备份与健康。首页将进行中训练/自由训练放在前面，范例、我的模板、日历和历史按任务分组。

测试：数量、稳定资源 ID、全部动作引用与计量目标正确；无自动重量处方；预览零写入；明确采用时全部保存；重复采用生成独立 ID；注入失败整体回滚；损坏资源报错；指南和来源离线可访问。

- [ ] **U6：整体验证与 App Store（R8；依赖 U1–U5）**

发行：按指定提交格式保存并推送代码；构建下一可用版本，核验正式签名、HealthKit 权限、图片/许可与隐私链接，上传 Apple，保存构建验证与正式等待审核凭据；保留手动发布、免费和销售范围设置。若 1.1 仍处于审核队列，先保留新构建与资料，再依 Apple 页面可用操作完成更新提交，避免误取消已发布版本。

## 流程与兼容性检查

训练入口→唯一活动训练→本机事务→完成→既有 Health 队列。模板与目录变更不会反向改写已开始/完成快照。重复点击和恢复都走同一活动训练门槛；保存失败由现有事务回滚并保留页面输入。无内容 API、账号或远端健康传输。

没有 `docs/solutions/` 或集中 critical-patterns 文件；直接采用已有 QA 经验：大字号滚动定位、扩展目录不能假定首屏某一行、UI 构建关闭字符串回写、测试只使用隔离数据域。

## 发布后的验证

发布负责人在首次安装和首次更新后核对：旧模板/历史数、收藏、同一活动训练恢复、开始与结束的幂等性、健康队列收敛。若出现记录缺失或重复健康副本，停止扩大测试并暂停自动同步，先导出脱敏业务备份；不做数据库破坏性降级。不新增监控上传服务。本轮完成标准是实现和验证六项并成功送审，不包括 Apple 必须批准。
