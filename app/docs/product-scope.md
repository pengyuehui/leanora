# Leanora 0.1：阶段 1–5 范围

日期：2026-10-20。对应主开发计划 U1–U5。本目录是独立实现的原生 iPhone 工程，内部品牌 Leanora，开发 Bundle ID 为 `app.leanora.dev`。默认最低 iOS 18，简体中文优先，无账号和网络服务。

2026-10-21 发布身份更新：工程现使用 `ai.leanora.fitness`，团队 Manyao Li（`8ZP3NMT2A8`）；上文保留阶段 1–5 的历史标识。签名协议门槛及数据迁移边界见 [发布身份记录](qa/release-identity.md)。

## 本阶段交付

| 能力 | 当前行为 |
|---|---|
| 首次使用 | 欢迎 → 单位与可选目标 → 可选健康访问 → 首页；返回上一步可修改，跳过健康不阻塞进入 |
| 五个 Tab | 今天、训练、饮食、趋势、我的；每个 Tab 独立导航，首页入口可切换到对应区域 |
| 偏好 | 公斤/磅、公里/英里、每周训练天数、每日手填热量目标；保存后立即生效，重开保留 |
| 输入校验 | 目标可空；训练天数 1–7；热量为 1–20000 的整数。此范围是输入边界，不是营养建议。无效输入不会覆盖原值 |
| Apple Health | 解释用途、选择读取/写入范围、调用原生系统授权、展示不可用/请求错误/请求完成；不推断读取是否被拒绝 |
| 通知 | 用户主动触发原生通知授权，查看允许/拒绝/失败状态，从系统设置返回后刷新 |
| 隐私与无障碍基础 | 可访问的本机数据说明、动态字体、深浅色、减少动态效果、主要操作语义与 44pt 以上触控区域 |
| 工程 | Swift 6、SwiftUI、HealthKit、UserNotifications、应用图标、权限说明、隐私清单、单元与 UI 测试目标 |

U2 已接入本地 SwiftData 数据库；UserDefaults 仅作小型 UI 偏好缓存。首次升级时迁入单位、周训练天数和每日热量目标，后续启动从业务库恢复；目标按生效日期保存，修改今天不会覆盖过去。

## 阶段 2 交付

领域覆盖身份、动作、模板与周安排、训练与逐组快照、食物和份量、餐食与营养快照、目标、身体测量、设备健康映射/游标/队列/抑制与外部摘要。业务与队列同一次提交；健康导入批次与游标同一次提交。SwiftData 明确关闭 CloudKit。

「我的 → 数据管理」支持版本化 JSON 导出、文件预检、冲突预览和确认导入；同身份按修订合并，不同身份需先导出当前资料并确认整库替换。升级前保存受保护的恢复副本，启动失败可重试或选择恢复副本；不会自动删除旧库。导入不会排出健康写入。

## 后续阶段

U3 已提供 22 条自有基础动作、名称/别名搜索、肌群/器械筛选、自定义编辑/归档及来源详情。模板支持计划组数、次数范围、负重、计时/有氧目标、休息、重复动作、重排、复制和删除；每周日期可配置，单次改期独立持久化。可启动当天安排，保存独立计划快照，重启后返回同一进行中训练；可确认放弃。

U4 已提供逐组训练、计时/休息、暂停恢复、超级组、RPE/RIR、历史编辑删除、容量与 PR；U5 已提供 300 条来源食物、离线搜索/份量、自定义/归档、快速热量、历史餐次复制、体重体脂和首页/周月趋势。无数据时保留真实空状态，生产构建不注入演示记录。详情见 [训练与饮食功能合同](workout-and-nutrition.md)。

Health 样本同步由 U6/U7 提供，CSV 和明确清除路径由 U8 提供。真实通知授权和系统排程已实现；横幅/锁屏送达与最低系统实际行为继续由真机验收。

HealthKit 目前只设置访问权限，不读取或写入样本。系统完成请求不等于全部授权，更不等于已经同步。活动能量与步数只申请读取；心率、睡眠、临床数据不申请。授权选择表示本次请求范围，不表示系统当前真实读取权限。

## 产品决定

- 参考 OpenGym、训记、薄荷的功能研究，代码、素材、文案和导航独立制作；没有这些产品的运行时依赖。
- 不根据身体资料自动生成热量目标；不收集首次使用所不必需的个人信息。
- 权限由用户主动开启；跳过、部分允许、全部拒绝或设备不可用，都不锁住主导航。
- 正式品牌、商用 Bundle ID、Developer Team、内容审核人员和真机矩阵在对应交付前落实；当前为本机开发配置。
