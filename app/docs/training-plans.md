# U3 训练计划合同

2026-10-20，独立实现。阶段 3 提供计划与开始入口，逐组执行由 U4 接续。

## 动作目录

随包 `Catalog/exercises.json` 包含 22 条原创名称/别名/器械/肌群/计量类型，固定 UUID 和内容来源。目录离线加载，默认不批量写入用户库；动作首次被模板使用时，与模板共同保存。用户持久化资料按 UUID 覆盖同 ID 目录条目（如个人归档状态）。每条可查看来源；自定义条目由用户创建。

搜索匹配名称或别名，支持中英文及大小写；肌群与器械可组合筛选。默认排除归档和删除条目。归档保留模板引用和历史快照；含归档动作的模板可编辑，但开始前需要替换或恢复。自定义名称/分类可编辑；既有训练保留原动作快照。

## 模板与目标

模板编辑使用独立草稿，取消不写库；有未保存修改时明确确认放弃。每个条目使用独立 UUID，同一动作可以多次出现；目标、排序和重复条目互不覆盖。可用项目菜单复制、上移、下移、移除，数据层规范化 order。模板复制分配新的模板/条目/超级组关联 ID，不复制周安排。

力量项目可设置组数、次数上下限及 kg/lb 负重；自重项目不强加负重；计时项目用秒，有氧可设置时间及 km/mi 距离；休息用秒。显示单位在边界转换，存储始终 kg/m/s。可选数值留空不填 0；无效数字与逆向次数范围被拒绝。编辑提交检查原 revision，过期草稿不会覆盖新版本。提交期间禁用输入；数字键盘和模板文本键盘有明确收起入口。

删除模板为 tombstone：移除未来周计划，保留历史 session、目录依赖和已有快照。

## 每周与单次安排

模板 scheduledWeekdays 使用 ISO 周一 1 至周日 7。周计划页面按日期展示当天来源，支持前后一天、今天、日期选择和每周配置入口。

`WorkoutDayChange` 是独立业务聚合，包含 templateID、originDate、destinationDate 和原时区。同一模板/原始日期仅一条有效改期。计算当天安排时排除原日期并加入目标日期，不修改模板，也不改变下一周。如果改回原日期，仅显示一个安排。移到本身已有周安排的日期会保留两个独立来源的训练安排。

只有当前日期可启动安排；将来的开始按钮禁用。已有非放弃 session 的来源安排不能再改期。改期提交前后不创建 session；每行开始和改期采用独立按钮样式，防止 SwiftUI List 自动样式联动。

## 开始与恢复

开始操作在同一个持久化 actor 中读取/校验/提交，无 await 插入中间步骤。空模板或归档动作被拒绝；已有 active/paused session 时返回现有 ID，并发点击不创建两场训练。

开始时复制模板名称、revision、备注、各项目 ID、动作名称/计量类型、计划组/次数/负重/时间/距离/休息。生成的实际组 ID 独立，actual 值、完成时刻均为空；计划值不冒充实际完成数据。修改目录或模板不改变已经开始的快照。

展开前先计算组数量与全库上限，超过 10 万业务对象则拒绝，避免恶意/超大导入模板在开始时展开数百万组。普通提交仍由 U2 完整校验和原子回滚保护。

session 归日采用实际开始时刻和所在时区，scheduleOriginDate 仅用于安排来源；单次改期不是修改已完成训练日期。进行中训练可从今天或训练 Tab 返回，重启读取同一 ID。当前界面展示计划并允许确认放弃；放弃保留记录，不计为完成，也不写 Health。系统时钟退回或恢复未来时刻的记录仍可安全放弃，结束时刻不早于开始。

## 兼容与边界

新增 schedule 业务类型和 optional 计划快照字段；SQLite 聚合 schema 仍为 v2。U2 备份缺少 optional 字段可读取，U3 备份包含单次改期和快照，保留 ID；不假定旧 App 可以降级读取新类型。健康设备状态继续排除，导入不排出写任务。

目录已做开发自检，不宣称专业教练审定。发布前约 100 条目录、最低系统/真机/VoiceOver 与大数据性能按后续发布门槛验证。
