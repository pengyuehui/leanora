# U4/U5 提交前顺序审查

2026-10-20。`ce:review` 流程按用户 AGENTS 工具映射，在主线程顺序执行，不声称有独立评审 agent。范围：相对基线 df8e515 的本次 app 功能；许可/构建边界、源数据生成、原生与 SwiftPM 验证。显式计划：docs/plans/2026-10-20-001-feat-training-nutrition-ios-plan.md 的 U4/U5。

## 检查范围

正确性、测试、维护性、项目约定、数据完整性、安全输入、可靠性、跨组件故障和计时状态。领域操作有独立持久化 actor 方法，UI 用原生控件及可查询标识；未引入产品计划以外的 agent/远程 API。项目无 docs/solutions 历史条目，复用 U2/U3 的快照/事务/备份/输入合同。生成食物数据逐项校验 ID、来源、单位及数值，不将营养专业审核伪装为开发校验。

## 已解决

- P1：暂停状态无暂停区间可在结束时越界。领域拒绝损坏状态、结束另有 guard，回归验证。
- P2：异步通知重建交错可能覆盖新期限。串行合并最新期望请求，终态和到期排除有测试。
- P2：同一动作的两个模板项目预填可能互相覆盖。优先匹配模板项目 ID，退回最近同动作；新增测试证明各自保留 20/30 kg 且未完成。
- P2：目标/备份变化后的日记缓存可能滞后。保存偏好和恢复完成后明确刷新。
- P2：多个弹窗之间切换的呈现边界不清。饮食和身体采用单一入口，饮食关闭完成前禁用新入口。
- P2：Duo 自动化读取过期滚动坐标。用录屏与层级核对，增加真实滚动及可见区域检查，连续饮食最终通过。没有通过修改营养计算去迎合测试。
- 清理已替换的日记空状态及无使用方协议；保留旧备份的 optional 新字段，未改变持久化 schema。

## 需求完整性

U4 R2/R5/R7、U5 R2/R6/R7 的本地功能均有实现与测试；U1/U8 设备门槛和内容专业审核保留。U6/U7 的 Health 样本同步明确未在本次范围中。任务/业务同事务、恢复不自动回写和外部抑制约束已检查。没有未解决的数据丢失或输入安全发现。

## 验证及发布风险

76 项单元、29 项 UI 采用完整回归和最新定向复测覆盖；原始失败及通过分别记录，未把非全通过的结果包改写为成功。正式 iPhone Release 构建和调试隔离通过。真实通知授权/排程另行记录；横幅与锁屏送达受当前 Duo 模拟器限制，真机待验。具体结果见 app/docs/qa/phase-four-five-verification.md。

结论：可提交本阶段本地功能。商业发布仍需原计划设备、内容及 U6–U8 验收。没有新增需用户批准的破坏性操作、推送或发布。
