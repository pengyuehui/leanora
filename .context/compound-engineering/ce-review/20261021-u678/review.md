# U6–U8 与记录体验提交前审查

2026-10-21。范围为基线 `eeb41ff` 后的源码、测试、生成工程、文档与新增证据。显式需求为主开发计划 U6–U8 及用户要求的训记风格/主流程优化。依据用户 AGENTS 工具映射，在主线程顺序执行 `ce:review` 的各审查视角，没有独立 agent 评审。

## 覆盖

正确性、测试、可维护性、项目约定、数据完整性、安全输入、可靠性、性能、接口合同及对抗性场景。重点检查恢复旧版本、部分权限、确认前崩溃、写入中编辑、后台写入时清理、未知营养组件删除、Health 手动删除和 CSV 输入。没有新增远程服务、运行时依赖或数据库实体。新运行时字段兼容旧可选值；不支持将健康状态库回退给 0.1 解码。

领域操作由持久化 actor 提供，UI 调用同一入口，宿主测试直接验证；系统健康授权仍由人完成。无需为该个人记录产品增加远程 agent 服务。未发现 docs/solutions 历史条目，复用既有阶段的事务、业务快照、备份门槛与原生弹窗呈现经验。

## 已解决的发现

- P1：清理可能与 observer 在途写入交错。配置必须先成功提交，engine 合并新信号，清理等待 UI 任务及 engine 空闲；故障注入和悬停写入测试通过。
- P1：旧备份可能丢失同步版本语义。恢复不排队，添加逐记录 hold，核对重建真实样本/版本下限，显式重导出才解除；版本 10→11 场景通过。
- P1：保存对象的暂存 UUID 不能证明 Health 实际接受版本。写入后必须查到真实样本与足够版本，否则保留失败任务；最终真实 SDK 模拟器写入/重复检查通过。
- P1：未知字段变更可能遗留上次写入成功但确认失败的组件。排队综合既有值、实际关联与已开始任务，逐组件删除；故障测试通过。
- P2：关闭自动同步不应丢失用户明确选择的副本删除。显式删除任务独立持久化、独立权限检查，启动时继续处理；普通本机删除保留副本。
- P2：全局清理部分成功后可能被编辑重新创建。先持久化抑制再删除；按本来源过滤，保留其他来源及本机业务。外部隐藏不由历史导出解除。
- P2：常规保存/任务处理不应反复解码十万外部样本。元数据与分页缓存分离，当前关联/抑制直接索引，业务快照由唯一写入 actor 在事务变更时失效；十万分页与持续主线程探针通过。
- P2：状态回调和并发刷新可能停留在旧快照。使用一致 actor 快照、刷新代次和 observer 更新回调，日活动类型加入观察范围。
- P2：系统文件导出和键盘遮挡影响完成路径。统一导出器、带时间文件名、结果滚动、顶部清除按钮和完成输入；原生 JSON 保存/重选/幂等导入及 CSV/重置复测通过。
