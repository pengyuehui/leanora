# U2 顺序审查

范围：显式计划 U2；App/Core 新领域、SwiftData/备份、入口和数据管理，以及新增测试。无 Git 仓库，按 U2 文件清单和本轮现有文件变更审查；研究 sources 不参与。

按用户 AGENTS.md，在主线程顺序采用 ce:review 的正确性、测试、可维护性、项目标准、数据完整性/迁移、安全与对抗检查，不生成子代理。没有额外项目 AGENTS/CLAUDE 标准或可用 docs/solutions。

## 已落实的修正

- 业务和任务/游标均只在单个 save 提交；失败统一 rollback，关闭 autosave。
- 组件变未知需删除旧 Health 组件，不能输出 0；测试覆盖。
- 导入预览加本机指纹，防止预览期间变化后覆盖；异身份要求当前导出与二次确认。
- 恢复不带设备健康状态，清队列并持久化核对门槛，普通保存不自动排出任务。
- 失败打开不清理旧恢复；恢复安装前落中断标记，启动不能误建空库。
- SwiftData 使用明确 versionedSchema；v1 实盘 fixture 用 SQLite backup 固定，迁移 ID 不变。
- 测试夹具、重置目录和失败注入全部为 Debug/隔离环境；Release 不包含。
- 导入按上限分块读取，无 URL 访问或执行，UUID/引用/枚举/数值/日期校验在写前完成。

## 需求完整性

U2 的 R2/R3/R11 数据基础、备份合同与所有指定测试场景已实现。DataManagementView 的 JSON 入口提前在 U2 提供可用验收；CSV/清除与发布整体保持 U8，训练/饮食 CRUD 保持 U3–U5，实际健康读写保持 U6/U7。

## 保留边界

物理文件保护/锁屏/VoiceOver、最低系统真机、U8 大数据性能未验证；保留为设备/发布验收项，不以模拟器替代。领域聚合以 Codable 值存储，后续查询/索引应按真实页面需求及基准实施，当前不承诺性能目标。

审查后无已知阻断 U2 的未解决代码问题。最终测试证据见 app/docs/qa/phase-two-verification.md；未执行提交、推送或发布。
